# RouteOptimizer

Проект реализован в рамках ВКР на тему"Разработка модуля планирования оптимального маршрута служебных командировок с интеграцией в 1С".

RouteOptimizer(Оптимизатор маршрутов) — это сервис на FastAPI для расчёта и оптимизации маршрута служебных командировок с учётом временных окон посещения, приоритета точек, суточного лимита вождения, времени посещения точки . Проект рассчитан на совместную работу с 1C, поэтому папка `1c/` входит в состав репозитория. За расчёт маршрутов отвечает комбинированный алгоритм(Ближайший сосед + Генетический, с некоторыми модификациями под поставленную задачу).

## Структура проекта

- `app/` — приложение FastAPI, логика оптимизации маршрутов, модели и вспомогательные функции
- `tests/` — проверки логики времени и маршрутизации
- `data/cache/` — runtime-кэш, создаваемый сервисом во время работы
- `1c/` — выгрузка конфигурации 1C, необходимая для полной связки решения
- `Dockerfile` и `docker-compose.yml` — запуск в контейнере
- `run_native.bat` и `setup_and_run.bat` — сценарии запуска для Windows

## Требования

- Python 3.11+
- Docker Desktop, если планируется запуск в контейнере
- Доступ в сеть для геокодирования и построения матриц маршрутов, если не используются собственные сервисы OSRM и Nominatim

## Переменные окружения

Сервис можно настроить через следующие переменные:

- `OSRM_URL` — базовый URL OSRM-сервера, по умолчанию `http://router.project-osrm.org`
- `NOMINATIM_URL` — адрес поиска Nominatim, по умолчанию `https://nominatim.openstreetmap.org/search`
- `OSRM_MATRIX_LIMIT` — ограничение на размер матрицы, по умолчанию `100`

В текущей реализации OSRM и Nominatim используются только через API. Проект не разворачивает и не поставляет эти сервисы локально.

## Локальный запуск

1. Установите зависимости:

```bash
pip install -r requirements.txt
```

2. Запустите API:

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

На Windows также можно использовать `run_native.bat`.

Рекомендуемый путь для большинства пользователей: `run_native.bat`.
Этот сценарий не требует Docker Desktop.

## Запуск в Docker

```bash
docker compose up -d --build
```

Либо запустите `setup_and_run.bat` в Windows.

`setup_and_run.bat` поддерживает оба варианта compose-команды (`docker compose` и `docker-compose`).
Если Docker недоступен или не запущен, сценарий автоматически переключится на `run_native.bat`.

## Тестирование

В репозитории есть тест проверки логики времени: `tests/test_time_logic.py`.

## Примечания

- В 1С необходимо импортировать файл конфигурации.
- Runtime-кэш в `data/cache/` создаётся автоматически во время работы.
- Папка `1c/` включена намеренно, так как без неё проект теряет свой смысл как связное решение.
- Интерактивная карта в 1C строится через LaFleet.
